title: Scopes
description: Every access token scope, what it implies, and the exact API operations and assistant tools each one gates.
---

A **scope** is a named permission an access token carries. When you create a
token you either grant full access or choose scopes; a scoped token can call
only the operations whose required scope it holds. This page lists every scope
and every operation it gates, generated from the scope table in
`api/internal/server/scopes.go` (`operationScopes`) and the tool registry in
`api/internal/ai`.

Scopes are a ceiling on top of the principal's role, never a grant beyond it: a
token can do at most what the person (or, for an organization token, the
service principal's role) could do. See [Roles matrix](/docs/reference/roles-matrix).

## How scopes combine

- **Parents imply children.** Holding a parent scope satisfies any operation that
  requires one of its children.
- **Full access** (a token created with no scopes) is not scope-limited at all;
  it is bounded only by the role behind it.
- **Fail-closed.** An operation with no entry in the scope table cannot be called
  by any scoped token. CI enforces that every registered operation is either
  scoped or explicitly listed as unreachable (the last section below).
- **One vocabulary.** Every assistant and MCP tool declares the same scope as
  the operation it fronts, so an MCP client authenticated with a scoped token can
  see and run only the matching tools. The documentation tools (`search_docs`,
  `get_doc`) are public and need no scope.
- **Some operations need a person.** An organization access token is refused
  with `403` on `create-org`, `leave-org`, `list-deleted-orgs`, and
  `restore-org`, whatever scopes it holds, because those act on a human's
  account.

## All scopes

| Scope | Grants | Implies |
| --- | --- | --- |
| `read:user` | Read your own account. | |
| `user` | Account writes. No operation needs it today: your profile is edited in the dashboard. | `read:user` |
| `admin:user` | Full account control. Reserved for destructive account operations; none is token-reachable today. | `user`, `read:user` |
| `read:org` | Read organizations, members, pending invitations, the security policy, SSO providers, the audit log and its configuration, and your recently deleted organizations. | |
| `write:org` | Rename an organization; manage members and invitations; change the security policy, SSO providers, and audit configuration. | `read:org` |
| `admin:org` | Create, leave, delete, and restore organizations. | `write:org`, `read:org` |
| `read:project` | Read projects, the deleted-projects archive, and each project's collaborators, teams, and owners. | |
| `write:project` | Create and update projects. | `read:project` |
| `admin:project` | Delete and restore projects; manage a project's collaborators, team grants, and owners. | `write:project`, `read:project` |
| `read:team` | Read teams, their members, and the projects they can access. | |
| `write:team` | Create and edit teams and manage their membership. | `read:team` |
| `admin:team` | Delete teams. | `write:team`, `read:team` |
| `notifications` | Read your notifications and mark them read or unread. | |

The `QUERY` rows below are the body-based twins of paginated lists (see
[Pagination and search](/docs/api/pagination)). They are not in the OpenAPI spec
but require the same scope as their `GET` form, and the `GET` form's tool covers
them.

## Account

### `read:user`

| Operation | Method and path | Tool |
| --- | --- | --- |
| `get-me` | `GET /me` | `whoami` |

### `user`

No operation requires `user` today; it implies `read:user`. Your profile is
edited in the dashboard, and the dashboard mirrors it into the API through
`PUT /me/profile` (`sync-profile`), which only the app can call: no access token
reaches it, whatever its scopes.

### `admin:user`

No operation requires `admin:user` today. It exists so destructive account
operations (such as deleting your account) have a scope when they become API
operations. Account deletion currently happens only in the dashboard.

in the dashboard refuses `restore_organization`, because a deleted
organization is outside every conversation's organization; restore it from
**Settings > Organizations**, the API, or MCP.

## Operations no access token can reach

These operations have no scope on purpose, so every access token, even a
full-access one, is refused. They are either public or callable only by the
dashboard with its internal credential.

| Operation | Method and path | Why |
| --- | --- | --- |
| `get-user` | `GET /users/{username}` | Public: a user's public profile. Needs no token at all. |
| `get-invitation` | `GET /invitations/{token}` | Public: the invitation landing page, where the invitation token is the credential. |
| `accept-invitation` | `POST /invitations/{token}/accept` | Dashboard only: the dashboard accepts the invitation on the invitee's behalf. |
| `create-pat`, `list-pats`, `revoke-pat` | `/me/tokens` | Dashboard only: tokens never manage tokens, so a token cannot mint or widen its own access. |
| `create-oat`, `list-oats`, `revoke-oat` | `/orgs/{slug}/tokens` | Dashboard only, for the same reason. |
| `ai-send-message` | `POST /ai/messages` | Dashboard only: the assistant itself. External agents use the [MCP server](/docs/ai/mcp). |
| `ai-execute-action` | `POST /ai/actions/execute` | Dashboard only: the assistant's confirm step for a proposed change. |
| `set-account-deleted` | `PUT /me/deleted` | Dashboard only: mirrors the account's deleted state. |
| `provision-sso-member` | `POST /internal/sso/provision-member` | Dashboard only: runs after the sign-in service verifies an SSO assertion. |
| `get-sso-provider-configs` | `GET /internal/sso/providers` | Dashboard only: full SSO configuration, secrets included, for the sign-in service. |
| `import-sso-provider` | `POST /internal/sso/providers/import` | Dashboard only: one-time adoption of providers registered before the API owned them. |

The content routes (`/docs`, `/roadmap`, `/changelog`), the health probes, and
the MCP endpoint are outside the OpenAPI spec and outside this table; see
[OpenAPI and clients](/docs/api/openapi).
