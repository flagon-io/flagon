Flagon is a developer platform for operating your engineering system: your **projects**, the
**organization** that owns them, and the **people and teams** who work on them, in one place. You
can use the hosted service at [app.flagon.io](https://app.flagon.io) or run the whole stack
yourself.

AI is a first-class way to operate Flagon, but never a requirement. Everything the assistant can do
is an ordinary API operation that you can also run from the dashboard or a script, so a team that
never opens the assistant still gets the full platform.

## Three front doors, one set of operations

You reach Flagon in three ways, and all three land on the same permission-checked operations in the
Flagon API:

```text
 ┌─────────────────┐   ┌─────────────────┐   ┌─────────────────────────┐
 │    Dashboard    │   │     REST API    │   │    Assistant and MCP    │
 │  app.flagon.io  │   │  api.flagon.io  │   │  Ask AI, mcp.flagon.io  │
 └────────┬────────┘   └────────┬────────┘   └────────────┬────────────┘
          │                     │                         │
          │ session             │ token                   │ tool calls
          └─────────────────────┼─────────────────────────┘
                                ▼
           ┌─────────────────────────────────────────┐
           │    Flagon API: one set of operations,   │
           │  permission-checked, one tool registry  │
           └────────────────────┬────────────────────┘
                                ▼
           ┌─────────────────────────────────────────┐
           │   Postgres, row-level security per org  │
           └─────────────────────────────────────────┘
```

- **Dashboard.** The web app at `app.flagon.io` holds your sign-in session and forwards every
  request to the API as you. It never writes domain data itself.
- **REST API.** `https://api.flagon.io` is the source of truth. Its OpenAPI spec is generated from
  the code, so the spec always matches what the server does. You call it with an access token. See
  [Using the API](/docs/api/using-the-api).
- **Assistant and MCP.** The **Ask AI** panel in the dashboard and the MCP server at
  `mcp.flagon.io` expose the same operations as tools from one shared registry. The in-product
  assistant runs read operations right away and proposes every change for you to confirm. See
  [The assistant](/docs/ai/assistant) and [MCP server](/docs/ai/mcp).

Because all three share one implementation, a capability added to the API is available in every
front door, and none of them can do more than you can: the same roles, scopes, and tenant isolation
apply everywhere.

## What you can do today

- **Organizations.** Create an organization, rename it, leave it, and soft-delete and restore it
  within 30 days. See [Organizations](/docs/platform/organizations).
- **People.** Invite people by email or username, assign org roles, and group members into
  **teams**. See [Members](/docs/platform/members) and [Teams](/docs/platform/teams).
- **Projects.** Create projects with a name, description, README, and repository URL; grant
  per-project roles to people and teams; assign project owners; delete and restore. See
  [Projects](/docs/platform/projects) and [Project access](/docs/platform/project-access).
- **Security.** Require two-factor authentication for members, configure single sign-on over OIDC
  or SAML, and set a base permission for member access. See [SSO](/docs/platform/sso) and
  [Two-factor](/docs/platform/two-factor).
- **Accountability.** Every change to an organization is written to an append-only audit log that
  owners and admins can read, and changes that affect you arrive as notifications. See
  [Audit log](/docs/platform/audit-log).
- **Automation.** Mint personal or organization access tokens limited by scopes, then drive
  everything over the REST API or MCP. See [Access tokens](/docs/platform/access-tokens).
- **The assistant.** Ask the assistant to do any of the above, or to answer questions from these
  docs. AI usage is metered per organization and capped by a daily limit.

## What is not built yet

<Callout type="warn" title="Not available yet">

Deployments, logs and observability, packages, SCIM provisioning, the `flagon` command-line tool
(a skeleton whose commands exit with code 3), and billing beyond the free plan limit of one owned
organization are not built. Pages for these areas are marked as planned. The **Roadmap** group
in the navigation covers where the platform is heading: connected context across your tools,
agents, an MCP hub, metrics, reusable skills, and governance.

</Callout>

what the product does now. The assistant and the MCP server read them through the `search_docs` and
`get_doc` tools, which means you can ask the assistant how something works and get an answer from
this text.
