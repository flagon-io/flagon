# Quickstart

By the end of this page you will have a flag you can flip from the console and
read from your application. It takes about five minutes.

You will need a Flagon workspace (organization). If you do not have one yet, an
invite from your team gets you in; then open the [console](https://app.flagon.io).

## 1. Create a flag

In the console, open **Flags** and choose **New flag**. For this walkthrough:

- **Key**: `new-checkout`. This is the stable identifier your code evaluates.
- **Type**: `Boolean`.
- **Description**: optional, but future you will appreciate it.

A boolean flag is created with two variants, `on` (`true`) and `off` (`false`).
By default it is off in every environment, so shipping the flag changes nothing
until you decide to turn it on.

<Callout tone="note" title="Flag keys are forever-ish">
The key is what your code references, so pick a clear, lowercase, hyphenated
name. You can rename the display name freely, but changing the key means
changing your code.
</Callout>

## 2. Create a client key

Evaluation is authenticated with a **client key**, and each key belongs to one
environment. Open **Flags → Client Keys**, pick **Development** for now, and create
a key.

The key is publishable, so you can copy it now or retrieve it anytime from the
console. Set it as an environment variable in your app:

```bash
export FLAGON_CLIENT_KEY="flagon_client_..."
```

<Callout tone="note" title="Publishable, not secret">
A client key is safe to ship in client code, like a Stripe publishable key. It
only evaluates flags, and only in its one environment. Anyone holding it can read
that environment's flag values, so keep secrets out of flag values. Revoke and
replace a key anytime from the Client Keys page.
</Callout>

## 3. Evaluate it from your app

Install the OpenFeature SDK and the OFREP provider for your language, then point
the provider at Flagon with your key and evaluate. Pick your language once (top
right) and it sticks across the docs.

The default value (`false`) is what your code uses if the flag can't be reached
or doesn't exist. Evaluation always returns a value, so a network blip never
throws in your request path.

## 4. Flip it and watch it change

Back in the console, open the flag, switch **Development** on, and set the
default variant to `on`. Run your snippet again:

```ts
const showCheckout = await client.getBooleanValue("new-checkout", false, {
  targetingKey: "user-123",
});

console.log(showCheckout); // true
```

That's the whole loop: change configuration in the console, and your app picks
it up on the next evaluation, with no deploy.

<Callout tone="note" title="Propagation">
A configuration change is reflected within a few seconds. Flagon serves flag
config from a short-lived cache on the evaluation path, so a change is live
almost immediately, not instantly to the millisecond.
</Callout>
