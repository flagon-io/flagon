# The Flagon API

Everything on Flagon is an API. The console is just a client of it, so anything
you can do by clicking, you can script. This page covers the API's shape;
each product documents its own endpoints (for example,
[Feature Flags management](/docs/feature-flags/management-api)).

## Base URL

```
https://api.flagon.io
```

Running Flagon locally, the API is at `http://localhost:3002`.

## Authentication

Most endpoints authenticate with an [access token](/docs/platform/authentication)
sent as a bearer token; the console uses your session cookie instead:

```http
Authorization: Bearer flagon_oat_...
```

Flag **evaluation** is the exception: it lives under `/ofrep/v1/...` and uses a
read-only [client key](/docs/feature-flags/client-keys). The credential model,
including how tokens are minted and revoked, lives in one place under
[Authentication & tokens](/docs/platform/authentication).

## Organization scope

Management endpoints are scoped to an organization by its slug:

```http
https://api.flagon.io/v1/orgs/{org}/...
```

The token must be authorized for that organization, an organization token issued
for it, or a personal token whose owner is a member. Requests are isolated per
organization at the database level, so a token can never read another
organization's data.

## Responses and errors

Responses are JSON, success and failure alike. Failures use one consistent
envelope so you can handle them uniformly. The envelope and every status code are
documented under [Errors](/docs/platform/api/errors), and the `429` response and
backoff headers under [Rate limits](/docs/platform/api/rate-limits).

## OpenAPI

The API publishes a machine-readable **OpenAPI 3.1** document you can feed to a
client generator or an API explorer:

```
https://api.flagon.io/openapi.json
```

The root (`GET /`) also returns a small hypermedia index that points to the
document and the main entry points. Every endpoint is registered in the document,
so the [REST reference](/docs/api-reference) is complete.
