# Incidents

**Incidents** turn the catalog into a reliability tool. When something breaks, you
declare an incident, attach the affected services, and Flagon routes it to the
owning team and lands the right runbooks on it. It's built on the services you
already describe in the [Catalog](/docs/catalog).

## Declaring an incident

From **Incidents**, choose **Declare incident** (owner or admin). You give it:

- **A title and severity** (SEV1 through SEV4, or whatever your
  [severity ladder](/docs/incidents/severity-levels) defines).
- **Affected services**: the catalog projects it impacts. The **owning team**
  auto-fills from the first affected service, so an incident always has an owner.

On declare, Flagon attaches every matching
[runbook](/docs/incidents/runbooks) — the org's default playbook, plus any scoped
to the incident's severity — so the recovery steps are already on the incident as a
checklist, and its steps fire as the incident progresses.

## The lifecycle

- **Timeline**: post updates as you learn more; an update can change the milestone
  (open → investigating → identified → monitoring → resolved → retrospective →
  closed). Runbook steps re-evaluate on each change, so a step scoped to "resolved"
  fires the moment you get there.
- **Retrospective**: once resolved, work the [RCCA](/docs/incidents/postmortems) —
  the writeup is editable throughout, and reaching the retrospective milestone marks
  it underway.
- **Resolve**: close it out. It drops off the open list and the affected projects'
  overviews.

Each project's overview shows its **open incidents**, so the catalog reflects live
reliability state.

## Over the API

```bash
# Declare
curl -X POST https://api.flagon.io/v1/orgs/{org}/incidents \
  -H "Authorization: Bearer $FLAGON_TOKEN" -H "Content-Type: application/json" \
  -d '{ "title": "Checkout failing", "severity": "sev1",
        "affectedProjectKeys": ["web"] }'

# Timeline + resolve
curl -X POST .../incidents/{number}/updates -d '{ "body": "Rolling back", "status": "identified" }'
curl -X POST .../incidents/{number}/resolve
```
