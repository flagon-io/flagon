# Evaluate with OpenFeature

[OpenFeature](https://openfeature.dev) is a vendor-neutral standard for feature
flags. Flagon implements its remote evaluation protocol (OFREP), so you use the
standard OpenFeature SDK for your language plus the **OFREP provider**, pointed
at Flagon by URL. There is no Flagon-specific client to adopt.

## Node.js (server)

Install the server SDK and the OFREP provider:

```bash
npm install @openfeature/server-sdk @openfeature/ofrep-provider
```

Register the provider once, at startup. The `baseUrl` is the Flagon API host;
the provider appends the OFREP path itself. Authenticate with your
[SDK key](/concepts/sdk-keys) as a bearer token.

```ts
import { OpenFeature } from "@openfeature/server-sdk";
import { OFREPProvider } from "@openfeature/ofrep-provider";

await OpenFeature.setProviderAndWait(
  new OFREPProvider({
    baseUrl: "https://api.flagon.io",
    headers: [["Authorization", `Bearer ${process.env.FLAGON_SDK_KEY}`]],
  }),
);
```

Then get a client and evaluate. The default value (second argument) is returned
if evaluation can't complete, so your request path never throws on a flag:

```ts
const client = OpenFeature.getClient();

const context = { targetingKey: "user-123", plan: "pro" };

const showCheckout = await client.getBooleanValue("new-checkout", false, context);
const theme = await client.getStringValue("theme", "light", context);
const limit = await client.getNumberValue("upload-limit", 10, context);
const config = await client.getObjectValue("ranking", {}, context);
```

### Why the value came back

When you need the reason and the variant (for logging or debugging), ask for the
full evaluation details instead of just the value:

```ts
const details = await client.getBooleanDetails("new-checkout", false, context);

console.log(details.value); // true
console.log(details.reason); // "TARGETING_MATCH"
console.log(details.variant); // "on"
```

### Setting context globally

If most evaluations share the same context (the signed-in user, say), set it
once so you don't thread it through every call:

```ts
await OpenFeature.setContext({ targetingKey: "user-123", plan: "pro" });

// No per-call context needed now:
const showCheckout = await client.getBooleanValue("new-checkout", false);
```

## Browser and mobile

For a web front end, use the Web SDK with the OFREP **web** provider:

```bash
npm install @openfeature/web-sdk @openfeature/ofrep-web-provider
```

```ts
import { OpenFeature } from "@openfeature/web-sdk";
import { OFREPWebProvider } from "@openfeature/ofrep-web-provider";

await OpenFeature.setProviderAndWait(
  new OFREPWebProvider({ baseUrl: "https://api.flagon.io" }),
);
```

<Callout tone="warning" title="Don't ship a Production key to the browser">
Anything in a browser bundle is public. A Production SDK key in front-end code
lets anyone read your full flag configuration. For untrusted clients, evaluate
on your own server and send only the resulting values to the browser, or use a
key scoped to a low-risk environment.
</Callout>

## Rotating tokens

If your key can change at runtime, use `headersFactory` instead of `headers`;
it is called before every evaluation, so a rotated key is picked up without
re-registering the provider:

```ts
new OFREPProvider({
  baseUrl: "https://api.flagon.io",
  headersFactory: () => [["Authorization", `Bearer ${currentSdkKey()}`]],
});
```

## Other languages

OpenFeature has SDKs for Go, Python, Java, .NET, PHP, Ruby, and more, each with
an OFREP provider. The shape is always the same: construct the OFREP provider
with Flagon's base URL and an `Authorization: Bearer` header, register it, then
evaluate. See the [OpenFeature SDK list](https://openfeature.dev/docs/reference/technologies/)
for your language, and the [REST reference](/evaluate/rest) if you would rather
call the protocol directly.
